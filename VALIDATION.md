# Compatibility and validation

Validated on 2026-11-16 with moonc 0.10.20 and moon 0.1.20261104.

## Completed checks

- 15 JavaScript unit tests cover image ownership, analytical vectors for all 20 SVG operations, fractional-alpha Porter-Duff operations, isolated versus pass-through opacity, layer clipping, persistent edits, insertion/deletion/reorder and PNG/ORA round trips.
- GitHub CI runs check, test and build for native, JavaScript, wasm and wasm-gc, plus a native executable consumer, formatting and generated-interface consistency. The run for commit 4817f91 passed all steps. Later commits must be assessed by their own runs.
- Independent Python ZIP/XML and Pillow validation checks compressed archive input, exact composited pixels, extension attributes/resources, archive layout, thumbnails, overwrite protection and vector-document view mode with byte-identical original export.
- `scripts/check_package.py` reads the exact name and version from moon.mod, packages it, checks included licenses, extracts it and runs an independent consumer in a temporary workspace.
- The real browser UI imported Krita's ORA, edited a nested layer's Chinese name and position, saved the ORA and reopened it. The edited name and position remained correct.

## Krita 5.3.4 interoperability

The official Windows portable build was used locally. The original Light study artwork is generated by this project.

1. Krita opened the MoonBit-generated ORA and independently exported PNG. Pixels matched the MoonBit merged preview exactly.
2. Krita rewrote the ORA, cropping layer resources and adjusting their offsets. MoonBit rendered that independently written ORA with exact equality to Krita's PNG. Both files are committed under fixtures/.
3. MoonBit modified a nested layer in the Krita-written ORA, changed position, opacity and blend operation, and wrote a new ORA. Krita opened and exported it as PNG and ORA. The maximum observed per-channel difference was 1 on a 0–255 scale. MoonBit read the rewritten file and matched within the same tolerance.

Run `python scripts/check_krita.py` to verify the committed independent fixture. To repeat the live edit and reopen test, pass the path of an installed Krita executable as its argument.

## Known additive-operation difference

A separate two-layer 2×2 experiment compared all 20 operations against Krita 5.3.4. For the tested fractional-alpha colors, 19 operations differed by at most 2 per channel. `svg:plus` differed substantially. MoonOpenRaster follows the W3C additive premultiplied-color and additive-alpha formula, tested analytically. Krita's result in this experiment retained source-over alpha.

For source RGBA (204,128,26,128) over backdrop (51,102,153,166), MoonOpenRaster produced (136,131,113,255), while Krita produced (164,157,137,211). This is an explicit interoperability limitation for additive layers. Exact visual equality for such documents is not claimed.

## Supported editing and viewing

Accurate editing/rendering is scoped to 8-bit raster PNG layers in sRGB channel space, nested groups, baseline SVG operations, canvas clipping and integer layer offsets. Group isolation defaults to isolate. Pass-through opacity multiplies child opacity. Obsolete group offsets do not move children.

Unknown operations, vector resources, 16-bit PNG and ICC-profiled input are available through structural inspection and original-preview view mode in the browser. That mode exports the original archive unchanged and disables editing. It does not promise color conversion, rasterization or semantic editing of unknown features.

Unknown attributes and extra resources are preserved for supported documents. Application-specific effects encoded in unknown attributes are not a claim of supported rendering semantics.

## Resource limits and platform status

Input archive limit is 256 MiB, with at most 4096 entries, 64 MiB expanded per entry and 256 MiB accumulated expanded resources. Decoded layer pixels are limited to 128 MiB in total, validated for imported and programmatically constructed documents. PNG layers and canvases are limited to 16,777,216 pixels, with each dimension at most 16,384. Nested trees are limited to 128 levels. The renderer applies a conservative 256 MiB logical RGBA-buffer depth budget; runtime object overhead is additional. Browser imports are limited to 32 MiB. These defaults can reject exceptionally large documents.

Native execution is verified on Linux CI. The local Windows environment has incomplete MSVC/SDK components, so Windows-native runtime behavior has not been verified. Browser and JavaScript CLI runs were verified locally on Windows.
